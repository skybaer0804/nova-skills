# Next.js Error Boundary

## Overview

React Error Boundary catches **render-phase errors only**. It does not catch errors in event handlers or asynchronous code (`setTimeout`, `fetch`).

**Errors Error Boundary does NOT catch:**
- Event handler errors → use `try/catch` inside the handler
- Async errors (`setTimeout`, `fetch`) → use `try/catch` + refer to `nextjs-error-logging`
- Server-side rendering errors → Next.js handles these and forwards them to `error.tsx`

## Which Boundary to Use

```
Where does the error occur?
  Entire route crashes          → error.tsx in the route directory
  Root layout crashes           → app/global-error.tsx
  Async Server Component        → error.tsx + Suspense boundary
  Isolate a specific widget     → custom <ErrorBoundary> component
  Event handler / async code    → try/catch (not Error Boundary)
```

## Enforcement Rules

| Pattern | Rationale | Allowed Exceptions |
|---------|-----------|-------------------|
| `error.tsx` required on every route that fetches data | Prevents white screen on server errors | Static pages with no data fetching may omit it |
| `app/global-error.tsx` required at root | Last line of defense for root layout crashes | - |
| `error.tsx` must have `'use client'` | Next.js requirement — build error if missing | - |
| Always provide a `reset()` button | Allows user recovery without a full page refresh | For unrecoverable errors (expired auth), `redirect()` is an acceptable replacement |
| Custom `ErrorBoundary`: `getDerivedStateFromError` + `componentDidCatch` pair | `componentDidCatch` enables logging integration | `getDerivedStateFromError` alone is allowed when logging is not needed |
| Do not expose `error.message` in production | Stack trace exposure is a security risk | `process.env.NODE_ENV === 'development'` guard is allowed |

## 1. Route Level: error.tsx

```tsx
// app/(route)/error.tsx
'use client'  // required

export default function Error({
  error,
  reset,
}: {
  error: Error & { digest?: string }
  reset: () => void
}) {
  return (
    <div role="alert" aria-live="assertive" className="flex flex-col items-center gap-4 py-12">
      <h2 className="text-lg font-semibold">Something went wrong</h2>
      <p className="text-sm text-muted-foreground">
        {process.env.NODE_ENV === 'development'
          ? error.message
          : 'Please try again later'}
      </p>
      <button
        onClick={reset}
        className="rounded px-4 py-2 bg-primary text-primary-foreground text-sm"
      >
        Try again
      </button>
    </div>
  )
}
```

`error.digest` — A hash generated by Next.js to correlate server and client errors. Use it for logging; do not expose it in the UI.

## 2. Root Level: global-error.tsx

```tsx
// app/global-error.tsx
'use client'

export default function GlobalError({ reset }: { reset: () => void }) {
  return (
    // Root layout is replaced — must include <html>/<body>
    <html lang="en">
      <body className="flex items-center justify-center min-h-screen">
        <div role="alert" className="text-center space-y-4">
          <h1 className="text-xl font-bold">Service temporarily unavailable</h1>
          <button
            onClick={reset}
            className="rounded px-4 py-2 bg-primary text-primary-foreground text-sm"
          >
            Refresh
          </button>
        </div>
      </body>
    </html>
  )
}
```

## 3. Custom ErrorBoundary Component

Use when isolating a specific widget without affecting sibling components.

```tsx
// components/ui/error-boundary.tsx
'use client'
import { Component, type ReactNode } from 'react'

interface Props {
  fallback?: ReactNode
  children: ReactNode
  onError?: (error: Error, info: { componentStack: string }) => void
}

interface State { hasError: boolean; error?: Error }

export class ErrorBoundary extends Component<Props, State> {
  state: State = { hasError: false }

  static getDerivedStateFromError(error: Error): State {
    return { hasError: true, error }
  }

  componentDidCatch(error: Error, info: { componentStack: string }) {
    this.props.onError?.(error, info)  // logging integration point
  }

  render() {
    if (this.state.hasError) {
      return this.props.fallback ?? (
        <div role="alert" className="p-4 text-sm text-destructive border border-destructive/20 rounded">
          Failed to load this section
        </div>
      )
    }
    return this.props.children
  }
}
```

```tsx
// Usage: widget isolation
<ErrorBoundary
  fallback={<WidgetSkeleton />}
  onError={(error) => logError(error)}
>
  <DashboardWidget />
</ErrorBoundary>
```

## 4. Suspense + ErrorBoundary Combination

When handling errors during streaming of async Server Components:

```tsx
// Suspense: handles loading / ErrorBoundary: handles errors
<ErrorBoundary fallback={<WidgetError />}>
  <Suspense fallback={<WidgetSkeleton />}>
    <AsyncWidget />  {/* async Server Component */}
  </Suspense>
</ErrorBoundary>
```

## 5. react-error-boundary Library (Optional)

Use when you prefer a declarative API over class components:

```tsx
import { ErrorBoundary } from 'react-error-boundary'

<ErrorBoundary
  fallbackRender={({ error, resetErrorBoundary }) => (
    <div role="alert">
      <p className="text-sm text-destructive">
        {process.env.NODE_ENV === 'development' ? error.message : 'An error occurred'}
      </p>
      <button onClick={resetErrorBoundary}>Try again</button>
    </div>
  )}
  onError={(error, info) => logError(error, info)}
>
  <ComponentThatMayFail />
</ErrorBoundary>
```

The `useErrorBoundary()` hook lets you programmatically trigger an Error Boundary from asynchronous code.

## 6. Event Handler Errors (Not Caught by Boundary)

```tsx
// ❌ ErrorBoundary does not catch this
<button onClick={() => {
  throw new Error('Error Boundary will not catch this error')
}}>

// ✅ Handle directly with try/catch
<button onClick={() => {
  try {
    riskyOperation()
  } catch (error) {
    setErrorState(error)  // or logError(error)
  }
}}>
```

## Common Mistakes

| Mistake | Fix |
|---------|-----|
| Missing `'use client'` in `error.tsx` | Add it as the first line — required |
| Missing `<html>/<body>` in `global-error.tsx` | Root layout is replaced — full HTML shell is needed |
| Exposing `error.message` in production | Add `process.env.NODE_ENV === 'development'` guard |
| No reset button | Always provide a user recovery path |
| Using ErrorBoundary for async errors | Use `try/catch` — Boundary handles render errors only |
| Displaying `error.digest` in the UI | Use it only in server-side logs |
